# ref-watch-logic -- /market watch thresholds, data contract, and response catalog

Read-on-demand companion to `.agents/skills/market/SKILL.md` (same pattern as
ref-risk-methodology). Owns: the exact data contract, the master severity
table, the pre-committed response catalog with citations, edge cases, and a
worked example. ASCII only. No network. Documents methods only -- carries no
live values (stale-literal failure mode F-R1). The standalone `/watch` skill
was absorbed into `/market watch` on 2026-08-24: `.agents/skills/watch/SKILL.md`
no longer exists and the original sits in
`.agents/skills/_archive/consolidated-2026-08-24/`.

## 1. Data contract

### 1.1 Entity surveillance (triggers lane)

- Glob: `wiki/maintenance/surveillance/entity-triggers-*.md`; use the file
  with the lexicographically greatest date stem. The file is GENERATED by
  `tools/entity-surveillance.py --proximity 8` (default is 10; /market watch's
  dashboard contract is 8 pct).
- Table columns: `| ticker | last | trigger | level | distance |`. Trigger
  grammar (per tools/entity-surveillance.py): `limit-buy (LIMIT)`,
  `near-zone (zone)`, MA50/MA200 anchors, kill-stop. Distance sign convention:
  positive = price ABOVE level (for limit-buys: not yet filled), negative =
  below.
- HELD vs watchlist classification source of truth: the HELD roster in
  `wiki/research/ref-earnings-calendar.md` (the held roster, resolved at run time). A ticker
  on the roster = HELD; everything else in the surveillance table is a
  watchlist entity.
- Staleness rule: if the newest surveillance file predates the store's last
  bar date by more than 3 trading days, emit an INFO staleness banner:
  rerun command is
  `python tools/entity-surveillance.py --proximity 8`
  (writes tomorrow-dated file; run only on operator request).

### 1.2 Earnings calendar (earnings lane)

- Source: `wiki/research/ref-earnings-calendar.md`, section "Calendar" --
  columns Date | Ticker | Company | Status | Exp. move | Key metrics | Binary.
- Status markers: `TENT` = tentative (no IR confirmation in vault); `CONF` =
  confirmed; `rolling` = continuous/index (exclude from dated alerts, may cite
  in lane summary). Ticker appears in the HELD set iff listed there.
- Trading-day arithmetic: count sessions forward from the run date using the
  bars table grid (`SELECT DISTINCT date FROM bars ORDER BY date`) as the
  trading calendar; "within N trading days" means the print date falls at or
  before the N-th future session. TENTATIVE dates inside 5 trading days get
  severity capped at WARNING + a "confirm with IR" note (a wrong date must
  never manufacture a CRITICAL).

### 1.3 Macro store (macro lane)

DB: `Efforts/osanwe-v2-overhaul/_work/factors.db`, table
`factors(ticker, date, factor, value, text_value, src)` with `ticker='MACRO'`.
Latest observation per series:

```sql
SELECT factor, date, value FROM factors
WHERE ticker='MACRO' AND factor=?
ORDER BY date DESC LIMIT 1;
```

Windowed variants (rate_shock, VIX streaks, WRESBAL/SOFR/RRP tripwires) are
the same query with `LIMIT n` / date filters -- exact windows per Section 3.
Series used: DGS10, DFII10, VIXCLS (always); STLFSI4, WRESBAL, WALCL,
RRPONTSYD, SOFR, FEDFUNDS, DEXJPUS (tripwires when macro mode or when any
CRITICAL fires elsewhere).

### 1.4 Liquidity engine conclusions

Source: `wiki/research/ref-fed-liquidity-engine.md`.
- Section 7 scoreboard (six dimensions + VERDICT line): quote VERDICT verbatim.
- Section 8 monitoring playbook: the six tripwire rows (WRESBAL, SOFR-
  FEDFUNDS, RRPONTSYD, DEXJPUS, STLFSI4, WALCL) with their action biases --
  these ARE the pre-committed responses for the liquidity block.

### 1.5 Filings (filings lane)

Per covered ticker: `wiki/investing/filings/<T>/<T>-filings.json` -- a JSON
array of `{ticker, form, date, desc, doc}`. Screen: newest entry where
`form == '8-K'`; alert if its date is within 5 calendar days of the run date.
Coverage = tickers appearing under wiki/investing/filings/. Report form,
date, and doc filename only; contents are never fetched (offline constraint).

## 3. Exact macro evaluations

- RATE_SHOCK (doctrine deployment.rate_shock): DFII10 up >= 75 bp over its 60
  most recent published observations AND nominal confirm DGS10 up >= 25 bp
  over the same span AND entered after 3 consecutive confirmed-fire sessions;
  state exits below +60 bp rise. Multiplier 0.5x while active; unknown reads
  treated-halted 0.5x. Compute the bp rise from the store directly; do NOT
  hardcode a prior reading.
- REGIME_THROTTLE: VIXCLS > 22 on ALL of the 5 most recent observations ->
  0.5x. REGIME_HALT: VIXCLS > 35 on ALL of the 5 most recent -> 0.0x
  (absolute). Reserve-release vix-spike arm: ANY of the 5 most recent > 30
  (release itself still requires its other conditions -- report ARMED only).
- Stacking: multipliers combine by MIN across active states, never multiplied;
  report the resulting single effective multiplier, never a product.
- DGS10: report level, 20-session delta, and the disclosure note that the
  level band ladder was retired 2026-07-30 (decision-invest-rate-gate-retire);
  a LEVEL alone is never a gate. It survives only as rate_shock nominal-confirm
  input and smoothed-Rf input.
- Tripwires (engine Section 8, quoted thresholds):
  - WRESBAL: < 2,800 B sustained 4-wk avg -> reserves leaving defended band.
  - SOFR minus FEDFUNDS: > +10 bp for 3+ consecutive sessions off quarter-end
    -> structural scarcity (de-risk into strength).
  - RRPONTSYD: re-inflating > 100 B -> bill supply/demand dislocation
    (investigate before assuming liquidity add).
  - DEXJPUS: fast rally > 3 yen within <= 5 sessions from a base > 158 ->
    carry unwind in motion.
  - STLFSI4: crossing 0 then +0.33 -> conditions normalizing then stressing
    (raise cash buffer systematically).
  - WALCL: renewed weekly declines > 30 B for 3+ weeks -> drain resumption
    (fade risk appetite until reversed).

## 4. Pre-committed response catalog (verbatim doctrine anchors)

- R-KILL: kill-stop is a hard exit level pre-agreed in the entity thesis;
  touching it routes IMMEDIATELY to `/gate f` adjudication + `/decide`
  record; no averaging-down, no discretionary pass. (entity kill-stop lines +
  doctrine stop_rules.)
- R-RATE-SHOCK: deployment multiplier drops to 0.5x; new adds sized at 0.5x
  computed size; analysis/rating unaffected (scope clause). Piercing requires
  the override_lane (explicit user directive, verbatim disclosure).
- R-HALT: regime halt 0.0x absolute -- NO new deployments; existing holds
  unchanged; report only. Same override-lane rules as R-RATE-SHOCK.
- R-CARRY: cut correlated risk FAST; vol hedges over delta hedges (engine
  Section 8 action bias, quoted).
- R-WRESBAL: reduce leverage; expect Fed tool talk (SRP / standing repo usage)
  (engine Section 8, quoted).
- R-PREP: enter pre-earnings protocol NOW (doctrine Section 6 earnings-week
  tier); confirm plan exists: size decision BEFORE the print, no new money
  into an unprepared binary, implied-move check queued.
- R-TRIGGER: name enters the day's active-decision list; route through
  `/gate f` if action is contemplated; otherwise watchful hold.
- R-LIMIT: fill is imminent -- verify the order still reflects current thesis
  (`/gate f` re-check); never cancel or chase without a decision record.
- R-VIX-THROTTLE: deployment throttle 0.5x until VIX closes back <= 22 for
  the sustained window; routine management continues.
- R-RESERVE-ARM: cash-reserve release condition vix-spike is one check away
  (needs its remaining conditions); do NOT pre-release; surface to operator.
- R-EARN-WEEK: daily countdown in briefings; analyst revision trend + implied
  move surfaced; catalyst-calendar flag every day (doctrine Section 6).
- R-FILING: read the filing next session (operator fetches; skill stays
  offline); flag thesis-relevant deltas to the owning entity note pipeline.
- R-LIQ-*: use the engine Section 8 action bias for the tripped row, quoted.
- R-AWARE: log only; no action.
- R-EARN-MONITOR: heightened monitoring window opens (doctrine Section 6
  pre-earnings tier).
- R-STALE: emit staleness banner + regeneration command; ask operator whether
  to run it; never regenerate unprompted.

## 5. Edge cases

- Surveillance file missing entirely -> CRITICAL-gap? No: emit WARNING gap row
  (surveillance is regenerable) + R-STALE banner with command; other lanes run
  normally.
- Calendar lists a ticker absent from the surveillance table (no stored
  triggers) -> skip silently; coverage asymmetry is known, not an alert.
- Store last bar older than 7 calendar days -> global INFO freshness banner;
  all distance math flagged approximate.
- Conflicting dates between calendar and entity note -> calendar wins (it is
  the consolidated ref); note the conflict in the alert line.
- Duplicate trigger rows for one ticker (e.g., multiple AVGO MA200 anchors):
  report each row that crosses a severity threshold; collapse identical-class
  neighbors (< 0.5 pct apart) into one line listing both levels.
- Weekend/holiday run: use the most recent session's close throughout; say so
  in the freshness line.

## 7. Limitations

- Offline: distances reflect the store's last bar, not live prices; AH moves
  invisible (by design -- doctrine anchors regular-market-close anyway).
- Trigger parsing inherits tools/entity-surveillance.py grammar; free-text
  stops phrased unusually may be missed upstream (not this skill's failure).
- Calendar dates are vault-provenance only; TENTATIVE means unconfirmed.
