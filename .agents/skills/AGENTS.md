# Skill authoring (binds work under .agents/skills/ -- CANON tree) -- canonical

> Every harness reads this file on its walk into `.agents/skills/` (Codex/OpenCode/Goose/Crush/Cline/Pi natively; Claude Code via the `.claude/skills/AGENTS.md` pointer). This is the skill-authoring rulebook; author rules HERE.

- `.agents/skills/<name>/` is the CANONICAL home of every skill (SKILL.md + ref-*.md + scripts/ + assets/). `.claude/skills/<name>/` is a GENERATED derived copy (`.agents/scripts/sync.py`); NEVER hand-edit a derived file -- edit canon, re-run sync, commit both together. Consistency: `python .agents/scripts/checkall.py`.
- MIGRATION WINDOW (S3, 2026-08): a canon SKILL.md still carrying the legacy "CODEX ADAPTER" marker is an unmigrated stub -- for those skills the live `.claude/skills/<name>/` remains canonical until their batch lands; sync/driftcheck skip them.
- Before building or materially extending any skill: `/gate b` (root invariant; sheet + registry row via tools/gate-eval.py).
- Canon frontmatter is SPEC-ONLY (agentskills.io): top-level `name` (== dirname, 1-64 lowercase-hyphen, no '--') + `description` (double-quoted, ASCII, <= 500 chars hard cap, median target ~300, trigger keywords in the first 200 chars, any Distinct-from disambiguation preserved in substance) + `metadata` (string->string map carrying every Osanwe field stringified: osanwe-risk, osanwe-effort, osanwe-arguments, osanwe-argument-hint, osanwe-allowed-tools space-separated, osanwe-categories, osanwe-type, osanwe-status, osanwe-created, osanwe-updated). NO top-level allowed-tools in canon -- sync re-materializes it in the Claude derived copy from metadata (no privilege widening).
- SKILL.md body: lean main file, aspirational <=263 lines; detail in one-level-deep `ref-*.md`. Legitimate multi-phase skills keep full content inline -- vault-audit X2 flags HARD DRIFT only above 900 lines. Quality preservation beats line-count extraction.
- Subagent-bearing phases use harness-conditional dispatch phrasing: dispatch the named subagent when an Agent tool exists; otherwise execute the documented inline fallback (every such skill carries it verbatim). No skill conditions behavior on model identity. DW-topology skills: sequential spine is the universal fallback; fan-out concurrency <=6; budgets via `<SKILL>_DW_TOKEN_BUDGET` env vars.
- Shared-discipline primitives (F11/F14/F17, F.halt, Pattern 6, Pre-Output HALT gate, Phase J.0/O.0 pre-commit audit gate, FOLLOWUPS:skills): Vault Codex Section 4 glossary; canonical F11 lifecycle: Atlas/sources/meta/ref-execution-discipline.md.
- Registry of record: Vault Codex Section 4 (+ changelog for post-2026-07-06 changes). Retire skills to `.claude/skills/_archive/` (never-touch for sync), never delete.
- Done-bars for a new/edited canon skill: strict YAML parse; `python skeleton/eval/eval-skill-overlay.py --check` exit 0 (canon-spec schema); `agentskills validate` (PyPI skills-ref) pass; `python .agents/scripts/checkall.py` green.
