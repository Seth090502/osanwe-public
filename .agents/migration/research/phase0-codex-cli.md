## Extras

**(a) Skills trust/approval model.** No dedicated skill trust store documented (hooks have explicit `/hooks` trust review). Controls: `[[skills.config]]` path+enabled (requires restart); granular `skill_approval` (approval prompts for skill script execution; false auto-rejects); skill `scripts/` run under normal sandbox + approval policy; PreToolUse hooks fire on the calls a skill makes, so **hook-based veto is the practical enforcement layer for skills**.

**(b) Auth model.** Two paths: (1) **Sign in with ChatGPT** -- recommended; covered by Plus, Pro, Business, Edu, Enterprise; (2) **API key** (additional setup). CLI: `codex login` / `codex logout` / `codex login status`. **Blocker for a conformance run: `codex login status` on this machine returns `Not logged in`.**

**(c) Empirical feature flags (this machine, v0.118.0):** `codex_hooks` = under development / **false**, `multi_agent` = stable/true, `plugins` = stable/true, `skill_mcp_dependency_install` = stable/true, `child_agents_md` = under development/false, `memories` = under development/false, `tool_search` = under development/false. Current docs say hooks are on by default -- **hooks require an upgrade past 0.118.0 to exercise**.

**(d) Doc contradiction.** `docs/install.md` still lists "Windows 11 via WSL2" -- stale, contradicted by README's native PowerShell installer + shipped win32-x64 binaries + working native install here.

**(e) Doc-host migration.** developers.openai.com/codex/* now 308-redirects to learn.chatgpt.com/docs/*. GitHub docs/*.md are thin stubs.
